1. PROJECT OVERVIEW
================================================================================

  Duta Analytics Web2 is a single-page marketing and product showcase website
  for Duta Analytics Sdn Bhd. It presents industrial SaaS products including:

    - Factory Telemetry & Process Dashboards
    - Enterprise A.I Vision Inspection
    - Spatial GIS & Site Intelligence
    - 3D Asset & Digital Twin Modeling

  The site is a static front-end application (no backend server). It uses a
  contact form powered by Formspree (third-party form endpoint).

  Live URL : https://www.dutaanalytics.com/

  SOURCE CODE — src/
  ──────────────────

  src/main.tsx
    APPLICATION ENTRY POINT. This is the first code that runs.
    Execution order:
      1. Imports errorLogger and installs global error listeners
      2. Forces scroll restoration to top of page
      3. Creates React root on <div id="root">
      4. Renders <StrictMode> → <ErrorBoundary> → <App />

    Links to:
      → src/errorLogger.ts (installs global error capture)
      → src/components/ErrorBoundary.tsx (wraps entire app)
      → src/App.tsx (main application component)
      → src/index.css (global stylesheet)

  src/App.tsx
    MAIN APPLICATION COMPONENT. Orchestrates all sections.
    On mount (useEffect):
      1. Forces scroll to top
      2. Initialises Lenis smooth scroll engine
      3. Syncs Lenis with GSAP ScrollTrigger ticker
      4. Sets up IntersectionObserver for entrance animations
    Render tree (in order):
      <Loader />
      <TechCanvas />
      <Header />
      <Hero />
      <main>
        <DashboardSection />
        <DashboardVideoSection />
        <SolutionsSection />
        <SpatialSection />
        <DigitalTwinSection />
        <VisionSection />
        <AboutSection />
        <CaseStudiesSection />
        <StandardsSection />
        <ContactSection />
      </main>
      <Footer />
      <ErrorLogViewer />

  src/index.css
    MASTER STYLESHEET & DESIGN SYSTEM. Contains:
      - CSS custom properties (:root) for colors, spacing, typography
      - Fluid responsive spacing tokens using clamp()
      - Fluid dynamic typography scale (--text-xs through --text-4xl)
      - Lenis structural CSS overrides
      - Global element resets (*, html, body, a, button)
      - Container utility (.container) with fluid margins
      - Page loader styles (#loader, .loader__*)
      - Tech canvas overlay styles (.tech-canvas)
      - Header navigation styles (.vectr-header, .vectr-nav, etc.)
      - Hero section layout (.hero-section, .hero-title, etc.)
      - Section layout primitives (.page-section, .section-title, etc.)
      - Feature card grid (.features-grid, .feature-item)
      - Process grid (.process-grid, .process-card)
      - Standards banner dark block (.standards-section)
      - FAQ accordion (.faq-section, .faq-item)
      - CTA section (.cta-section, .cta-box)
      - Footer layout (.vectr-footer)
      - Flow section steps (.flow, .flow__step, .flow__track)
      - Responsive table horizontal scroll (.responsive-table-container)
      - Media queries at 1024px, 900px, and 640px breakpoints

  src/App.css
    Legacy/secondary stylesheet from Vite scaffold.
    Contains old counter and hero layout styles (mostly unused).

  src/errorLogger.ts
    GLOBAL ERROR CAPTURE SERVICE. Singleton module that:
      - Listens for window "error" events (runtime JS errors)
      - Listens for window "error" events on capture phase (resource loads)
      - Listens for "unhandledrejection" events (Promise failures)
      - Intercepts console.error calls
      - Accepts manual error logs from ErrorBoundary
      - Persists all entries to localStorage under key "duta_error_log"
      - Enforces a rolling cap of 200 entries maximum
      - Dispatches custom "duta-error-logged" events for live UI updates
      - Exports: installGlobalErrorListeners(), getErrorLogs(),
        clearErrorLogs(), exportErrorLogs(), logError()

    Each log entry contains:
      id, timestamp, type, message, source, lineno, colno,
      stack, componentStack, url, userAgent

4. APPLICATION BOOT SEQUENCE
================================================================================

  When a user loads the website, the following happens in order:

  Step 1 — Browser loads index.html
           Fonts begin preloading (Inter, Outfit, Space Grotesk)
           <div id="root"> is empty

  Step 2 — Vite loads src/main.tsx
           installGlobalErrorListeners() runs immediately
           → Attaches window error, unhandledrejection, resource error,
             and console.error interceptors

  Step 3 — React mounts <StrictMode> → <ErrorBoundary> → <App />

  Step 4 — <Loader /> renders full-screen loading overlay
           1200ms timer starts

  Step 5 — <TechCanvas /> mounts, starts rendering background grid

  Step 6 — <HeroFrameCanvas /> begins loading 300 WebP frames
           Frames load in parallel via new Image() objects

  Step 7 — App useEffect runs:
           a) Lenis smooth scroll engine initialises
           b) Lenis syncs with GSAP ScrollTrigger
           c) IntersectionObserver attaches to section elements

  Step 8 — After 1200ms, Loader fades out via CSS transition
           User sees the hero section with frame animation

  Step 9 — User scrolls → HeroFrameCanvas advances frames
           → Lenis provides smooth momentum
           → ScrollTrigger drives parallax transforms
           → IntersectionObserver triggers entrance animations

6. DATA FLOW & DEPENDENCIES
================================================================================

  SCROLL DATA FLOW:
  Lenis (smooth scroll) → GSAP ScrollTrigger → HeroFrameCanvas
       ↓                                            ↓
  Updates scroll position                 Reports frameIndex, textProgress
       ↓                                  exitProgress to Hero component
  IntersectionObserver                          ↓
       ↓                                  Hero applies parallax transforms
  Adds .show / .is-visible                to text and section opacity
  classes on sections

  ERROR DATA FLOW:
  Window error events ─────┐
  Unhandled rejections ────┤
  Resource load failures ──┤──→ errorLogger.ts ──→ localStorage
  console.error calls ─────┤                          ↓
  ErrorBoundary catches ───┘              ErrorLogViewer reads & displays

  FORM SUBMISSION FLOW:
  ContactSection form → fetch POST → Formspree API (external)
                                        ↓
                                   Success/Error response
                                        ↓
                                   UI state update

8. SCROLL & ANIMATION ENGINE
================================================================================

  THREE SYSTEMS WORK TOGETHER:

  1. LENIS (Smooth Scroll)
     - Provides momentum-based smooth scrolling
     - Duration: 1.2s, custom easing curve
     - Synchronised with GSAP ticker via lenis.raf()

  2. GSAP ScrollTrigger
     - Maps scroll position to animation progress values
     - Used by HeroFrameCanvas for frame-by-frame image sequence
     - Drives hero section parallax exit transitions

  3. IntersectionObserver (Native Browser API)
     - Observes: .flow, .feature-item, .process-card, .standards-banner,
       .faq-item, .page-section
     - On intersection: adds .show and .is-visible CSS classes
     - Triggers one-time entrance transitions

  4. Framer Motion (React Animation Library)
     - Used for individual component animations
     - whileInView, whileHover, AnimatePresence for expand/collapse
     - Spring physics for card hover effects

9. ERROR LOGGING SYSTEM
================================================================================

  PURPOSE: Captures all client-side errors for debugging.

  FILES:
    src/errorLogger.ts              — Core capture & storage service
    src/components/ErrorBoundary.tsx — React crash boundary
    src/components/ErrorLogViewer.tsx — Debug viewer panel

  WHAT IT CAPTURES:
    Type                  | Source
    ─────────────────────|──────────────────────────────────────
    runtime              | window.addEventListener("error")
    unhandled-rejection  | window.addEventListener("unhandledrejection")
    resource             | error event on capture phase (images/scripts/css)
    console              | console.error() intercept
    react-boundary       | ErrorBoundary.componentDidCatch()

  STORAGE:
    Location: localStorage key "duta_error_log"
    Format:   JSON array of ErrorLogEntry objects
    Max Cap:  200 entries (oldest are trimmed)

  VIEWER ACCESS:
    Keyboard shortcut: Ctrl+Shift+E (or Cmd+Shift+E)
    Also: floating red badge in bottom-right corner when errors exist

  VIEWER FEATURES:
    - Filter by error type
    - Click to expand full stack trace
    - Export as .json file
    - Clear all logs
    - Live-updates via custom "duta-error-logged" event

10. BUILD & DEPLOYMENT
================================================================================

  DEVELOPMENT SERVER:
    npm run dev         — Starts Vite dev server (default port 5173)
    npm run start       — Starts Vite on 0.0.0.0 (network-accessible)

  PRODUCTION BUILD:
    npm run build       — Runs TypeScript check + Vite production build
                          Output: dist/ directory
                          Generates: index.html, CSS bundle, JS bundle

  PREVIEW PRODUCTION BUILD:
    npm run preview     — Serves dist/ locally for testing

  LINTING:
    npm run lint        — Runs OxLint code quality checks

  DEPLOYMENT:
    The dist/ folder is a fully static site.
    Can be deployed to any static hosting:
      - Vercel, Netlify, Cloudflare Pages
      - AWS S3 + CloudFront
      - Any web server serving static files

  IMPORTANT BUILD NOTES:
    - The JS bundle exceeds 500 KB (due to Three.js + all components)
    - Consider code-splitting with dynamic import() for production
    - Video files in public/assets/ are large (20–34 MB)
    - Frame images total ~7 MB (300 WebP files)

11. COMMON ISSUES & TROUBLESHOOTING
================================================================================

  ISSUE: White/blank screen on load
  ─────────────────────────────────
  Possible causes:
    a) JavaScript build error — run "npm run build" to check for TS errors
    b) Missing dependencies — run "npm install" to restore node_modules
    c) ErrorBoundary caught a crash — check Ctrl+Shift+E error log panel
    d) index.html missing or wrong path — verify dist/index.html exists

  ISSUE: Hero animation not playing / black screen in hero
  ────────────────────────────────────────────────────────
  Possible causes:
    a) Frame images missing — verify public/assets/frames/ has 300 .webp files
    b) Frames failed to load — check browser Network tab for 404 errors
    c) Check Ctrl+Shift+E for "resource" type errors

  ISSUE: Smooth scrolling not working
  ───────────────────────────────────
  Possible causes:
    a) Lenis failed to initialise — check console for Lenis errors
    b) GSAP ScrollTrigger conflict — ensure only one ScrollTrigger instance
    c) CSS overflow-x: hidden on body may conflict

  ISSUE: Video not playing
  ────────────────────────
  Possible causes:
    a) Video files missing from public/assets/
    b) Browser autoplay policy blocks unmuted video
       (videos are set to muted + autoPlay by default)
    c) Video codec not supported — MP4 H.264 required

  ISSUE: Contact form not submitting
  ──────────────────────────────────
  Possible causes:
    a) Network error — check internet connection
    b) Formspree endpoint changed — verify URL in ContactSection.tsx
       Current endpoint: https://formspree.io/f/mzdwqwpw
    c) CORS error — Formspree handles CORS, check browser console

  ISSUE: Fonts not loading / fallback fonts visible
  ─────────────────────────────────────────────────
  Possible causes:
    a) Google Fonts CDN unreachable (blocked network/firewall)
    b) Preconnect links missing in index.html <head>
    c) Font family names misspelled in CSS

  ISSUE: Mobile navigation not showing
  ────────────────────────────────────
  The hamburger menu only appears below 900px viewport width.
  Check: browser DevTools responsive mode to simulate narrow screen.

  ISSUE: 3D model not rendering
  ─────────────────────────────
  Possible causes:
    a) WebGL not supported by browser
    b) hero-model.glb/gltf missing from public/assets/
    c) Three.js loading error — check console

  ISSUE: Error log panel not opening
  ──────────────────────────────────
  Press Ctrl+Shift+E (or Cmd+Shift+E on Mac).
  If still not working:
    a) ErrorLogViewer component may not be mounted — verify App.tsx imports
    b) Keyboard shortcut blocked by browser extension

  ISSUE: Build warning "chunks larger than 500 kB"
  ────────────────────────────────────────────────
  This is a Vite warning, not an error. The JS bundle is large because
  Three.js and all components are bundled together. To resolve:
    - Use dynamic import() for heavy sections (Three.js, DashboardSection)
    - Configure Vite rolldownOptions.output.codeSplitting

  ISSUE: localStorage "QuotaExceededError"
  ───────────────────────────────────────
  The error logger stores up to 200 entries in localStorage.
  If localStorage is full from other sites:
    a) Clear browser storage for this domain
    b) The error logger silently handles this — no crash will occur
